产品能力

三段式管线 × 六层契约 × 证据链

核心主张：交付的不是「一个 3D 模型」，而是「一组可审计的工程上下文」—— 几何、来源、验证状态、变更影响，全部结构化。

三段式管线

01
多源图纸接入 — 扫描图 / PDF / DWG / DXF → SourceRef（文件、版本、原始位置）
02
工程信息编译 — 构件 / 尺寸 / 连接 + BOM 交叉核验；冲突记为待验证而非静默丢弃
03
可信结果交付 — Harness 编排验证流程；GLB + model.json + 评测报告 + version.json 指纹链

角钢塔领域包：六层契约

每层只消费上一层产物；每层有独立可跑入口（run_layer）与审计契约， 层层可独立验证。

层产物审计契约（run_layer 核验项）
L1 drawing区域化 2D 构件（杆/节点/件号/DIM）每杆 SourceRef + geometry_class；label/dim 观测登记
L2 hypothesis结构解释候选（fan/twist/kchain）四态状态机（proposed/accepted/rejected/superseded）；观测普查
L3 rebuild参数化补全（面板链/横隔/终止节间）geometry_origin 全归因；节点三轴求解率
L4 semantic-IR语义工程模型 + BOM 交叉核验公共 IR schema；bom_tree 冲突披露
L5 validation-gate规则裁决 + 变更传播Rule.status 合法；failed/pending 逐条披露（不粉饰）
L6 complete-towerGLB / model.json / version.json指纹链闭合（model_sha ↔ 磁盘、overlay_sha）

核心数据模型

对象关键字段回答的问题
Componentid, kind, source这是什么？来自哪张图？
Dimensionvalue, unit, origin数值多少？实测（measured）还是推断（derived/assumed）？
Connectionfrom, to, rule_ids谁连谁？验证过吗？
Rulestatus, message这条规则过了没有？
dependenciesnode → upstreams改了它会作废谁？
stalenesscurrent / stale现在还有效吗？

依赖 DAG + 变更传播：上游尺寸被改，下游派生值自动置 stale—— 评测与门禁只认 current 状态。

多塔泛化纪律

换塔 = 改配置

view_regions（每册立面 z 域）/ z-only 层表覆写 / 终止节间跨度白名单 / 缝合容差——全部在 overlay.json。35A2-ZC1 换塔实测：引擎代码零改动。

跑批前预检

validate_workspace 五类把关：结构 / 册-区域一致 / GT 注入面 fail-closed（未知注入键直接拒）/ BOM 必须有杆件行 / GT 必须带来源说明。
