# DXF 里有什么：能直接读 vs 需要视觉读（附 35A1-JC1-02 实测）

> 回答一个反复出现的问题：**「CAD 文件里有什么数据，哪些能直接读出来，哪些必须用
> Kimi 视觉读？」** 本文用真实国网图 `35A1-JC1-02.dxf` 逐项实测，并修正了此前
> 文档里关于比例尺/视图的错误结论。

---

## 一、结论先行（一张表）

| 数据 | 能否直接读 | 方式 | 精度 |
|------|:---:|------|------|
| 杆件几何（线段/多段线端点坐标） | ✅ | ezdxf 矢量 | 100% 精确 |
| 尺寸标注（DIMENSION 的测量值+文字） | ✅ | ezdxf `get_measurement()` | 精确 |
| **视图比例尺** | ✅ | 见下「比例尺 = 1:20」 | 精确（三路交叉验证） |
| 标高/塔高（5800 等） | ✅ | DIMENSION 文字 | 精确 |
| ASCII 规格（L40X3 / M16X40 / Q345） | ✅ | ezdxf TEXT | 精确 |
| 图层 / 线型 / 单位 / 图幅 | ✅ | ezdxf 头 + 图层表 | 精确 |
| **中文文本**（表头/图名/视图标题/备注） | ❌ | SHX 形文件 `\M+XXXX` 乱码 | 需 Kimi 视觉 |
| **视图语义**（哪簇是正立面/侧视/详图） | ❌ | 二进制无标签 | 需 Kimi 视觉 |
| **件号 ↔ 杆件归属** | ⚠️ | 空间邻近（易错） | Kimi 更准 |

**核心判断**：几何 + 尺寸 + 规格 + 比例尺，占「数据量」大头，**二进制里就有，精确
值，直接读，不用猜、不用 Kimi**。只有「中文语义 + 视图关系 + 件号归属」这类「看图
才懂」的信息才需要 Kimi 视觉。两者互补，不是二选一。

## 三、★ 比例尺 = 1:20（不是 1:100，也不是 50.2/85.1）

这是本文最重要的修正。此前 `layer_overlay.json` 写 `scale_x=50.2 / scale_y=85.1`，
`docs/P0_P1_PROGRESS.md` 也据此论述——**都是错的**。正确值是 **scale_x ≈ scale_y ≈ 20**，
由三条独立证据交叉验证：

### 证据 1：DIMENSION 构件尺寸（34 处一致 = 20）

```
文字=380  测量=19.0  → 380/19.0 = 20.00
文字=400  测量=20.0  → 400/20.0 = 20.00
文字=430  测量=21.5  → 430/21.5 = 20.00
文字=365  测量=18.25 → 20.00
文字=375  测量=18.75 → 20.00
... 共 34 个 DIMENSION 全部 = 20
```

### 证据 2：BOM 主材长度（精确锚点）

BOM 材料表（件号 101-104）写 `Q345L70X5 长 5348mm`。该主材在 cluster1（塔身立面）
里的图面投影长 = 293.92 单位 → `5348/293.92 ≈ 18.2`（主材略斜，取竖直投影 293.20
→ 18.24）。**≈ 20**。

### 证据 3：GT 几何反推

GT（GIM 计算模型）里 L70X5 主材 z 36600→30800：正面水平位移 406mm、竖直位移 5800mm。
图面 dx=20.47、dy=293.20 → `scale_x = 406/20.47 ≈ 19.8`、`scale_y = 5800/293.20 ≈ 19.8`。
**≈ 20**。

### 为什么此前误判成 50.2/85.1 和 1:100

1. **`50.2/85.1`**：旧 `calibrate_view.py` 用 GT 反投影标定，把「标高 DIMENSION 的
   DIMLFAC=5 倍因子」混进了 scale，且把 front 框错指到别的簇。
2. **`1:100`**：标高刻度尺的 DIMENSION（`5800/58.14`、`1000/10.02`）看起来像 1:100，
   但那是 **DIMLFAC=5 的假象**：真实图面距离 = `measurement × 5`，再 × scale(20)
   才 = 文字值。即 `58.14 × 5 × 20 = 5814 ≈ 5800`。视图本身仍是 1:20。

### 塔头段高度 = 5800mm（DIMENSION 直接标注）

cluster1 左侧竖排标高刻度明确写了 `5800`（塔头段高）、`1900`、`1212`、`1000/900/
800/700/600/500/400`。`5800` 与 GT 的 L70X5 主材 z 段（36600−30800=5800mm）**完全吻合**。

## 四、视图布局（修正：不是 front+side，是「左塔 + 右塔」）

02 图几何按 x 分 3 个簇（gap>10）：

| 簇 | x 范围 | 宽×高(图面单位) | 判定 |
|----|--------|----------------|------|
| c1 | [34327, 34634] | 307.7 × 446.9 | **塔身主立面**（含竖直主材 293.2、标高 5800） |
| c2 | [34645, 34795] | 150.4 × 453.2 | 另一视图（水平横材长 81 为主） |
| c3 | [34808, 34899] | 91.6 × 523.9 | 窄段/详图 |

**关键修正**：Kimi OCR 与几何方向分布显示，c1 和 c2 是**两个并列的塔视图**（OCR 描述
为「左塔 + 右塔，对称布置」），**不是同一塔的「正面 + 侧面」**。因此：
- 「front+side 解耦」的 3D 路径对这张图**不成立**（没有真正的侧立面投影）；
- 正确 3D 路径是 **单立面 + 四向镜像（`expand_4_face_symmetry`）**，因为该塔是
  **正方形对称**（GT：x 半宽 = y 半宽 = 2762mm，节点 (200,±200)、（±200,200）成正方形四角）。

> 此前 `docs/KIMI_MLLM_FULL_TOWER_FINDINGS.md` 写「Kimi 识别出 front/side/plan 详图」
> 不准确；实际是多个塔段/视图横排，无独立 side 立面。

## 五、材料表（BOM）：右上角，可直接读

02 图右上角（x>34750）是材料表，件号 101~160（60 行），列序为：

```
件号(3位数字) | 截面 | 长度(mm) | 数量 | 单重 | 总重 | 备注(乱码)
    101       Q345L70X5  5348    1    28.86  28.9   \M+5C7D0...
```

- 件号列 x≈34952、截面列 x≈34961.5、长度列 x≈34992、数量列 x≈35004。
- 表头是 SHX 乱码，但**件号锚点**（件号后紧跟截面/长度/数量）可直接解析，
  已实现于 `traceability/intake/tower_bom.py::parse_bom_dxf_anchored`。
- 截面正则覆盖角钢（`L40X3`、`Q345L70X5`）与钢板（`-6X207`、`Q345-14X260`）。

## 六、正确分工（对实现的约束）

> **一句话**：该用 ezdxf 读的地方（几何 / 尺寸 / 比例）用 ezdxf，该用 Kimi 看的地方
> （语义 / 乱码中文）用 Kimi，**两者互补，不是二选一**。

1. **ezdxf 读**（二进制里就有的精确值）：几何、DIMENSION（比例尺 / 标高 / 构件尺寸）、
   ASCII 规格、图层线型。
2. **Kimi 视觉读**（看图才懂的语义）：SHX 乱码中文（表头/图名/视图标题）、视图语义、
   件号归属。
3. **比例尺**：用 DIMENSION 的「文字值/测量值」众数直接确定（本图 = 20），
   不要用 GT 反投影猜。
4. **3D**：对称塔走 `expand_4_face_symmetry` 四向镜像，不走 front+side 伪解耦，
   也不走 `synthetic_side_from_front`（45° 假斜片）。
