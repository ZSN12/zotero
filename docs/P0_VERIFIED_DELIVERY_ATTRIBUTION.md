## 四、跨塔事故修复：ZC1 legspan 8 杆被 dedup 吞（历史回归）

**现象**：ZC1 dual-recon 官方数字 Sep 5 266（93.3%）→ Sep 7 251
（88.1%），模型里 `leg_span_completion` 杆 0 根但生成器报告
`generated: 8`。

**定位（探针二分）**：`exact_overlap_dedup` 证据优先层
（715fbe8，2026-09-06）——逐环节探针显示 `exact_overlap_dedup:
legspan 8 → 0`，其余环节全保。

**机理**：旧判据 `ov ≥ 0.9×min(l1,l2)` 以两杆**较短者**为基准，
使「识别杆 ⊂ 补全杆」的**包含关系**也判重：05 册 dxf 腿杆
z 19223→26464（图纸截断证据，上界 26863）与 legspan 补全杆
19223→27400 共线重叠——识别杆被当主、补全杆被当「副本」整条
删除，[26464,27400] 外推增量段随之丢失（该段无任何图源，唯一
覆盖者就是 legspan）。

**修复**：删除候选 b 仅当 **b 被 a 完整覆盖**（`ov ≥ 0.9×len(b)`，
`base='b'`）——b 是 a 的副本才可删；a 比 b 短时 b 是互补外推段，
保留。3 单测锁定方向语义（真副本删 / 外推段保 / 等长双份删）。

**验证**：ZC1 dual-recon 251→259（R 90.9%），legspan 8 杆恢复；
JC1 全管线重跑红线逐位零回退（pure 304 / dual-recon 1067 R99.6%；
FP +90 为保留的外推段杆，P 32.3→31.5%，红线只约束 TP/R）。

**教训（写进判据）**：「删非证据副本」类规则的方向语义必须以
**被删杆自身**为覆盖基准；min(l1,l2) 基准在包含关系下会删掉
唯一覆盖无图源区段的补全杆。

## 八、P0-6：deliver_status 豁免通道机制（本轮落地，不含盖章）

6 件真 conflicts（三.2）的裁决需要横担详图人工核对——**AI 不替人工
盖章**。本轮只落机制：`traceability/project/delivery.py` 的
`_apply_review_exemptions` 扩展为双通道——

- **pending 豁免**（既有，2026-09-03 纪律）：消息指纹（sha256 前 16
  位）匹配 + `expires` 时效；生效后规则标 `review_exempted`
  （非 passed，报告永远可见）。
- **FAILED 豁免**（本轮新增）：额外要求豁免条目显式
  `confirm_conflict: true`——语义是人工裁决「该冲突经核对属图纸/
  模型数据分歧，模型侧维持现状」。无此标志的 FAILED 豁免一律拒绝
  （不静默改状态）。
- project harness（图册级）与单模型 harness 同纪律接线
  （`review_exemptions_file` overlay 键，相对路径优先按 overlay 目录）。
- 指纹不匹配 / 过期 / 规则已非 pending/failed → 豁免自动失效
  （防过期橡皮章）。

单测 `tests/test_review_exemptions.py` 10 例：pending 生效/指纹拒绝/
过期拒绝、FAILED 带 confirm_conflict 生效/缺失拒绝/指纹拒绝、
豁免≠passed 红线、文件缺失 no-op、passed 规则拒盖、坏 JSON 优雅降级。

**豁免文件本身不随本轮提交**——留给人工核对 6 件后填写（P0-1/P0-2）。
