# 35A1-JC1 比例尺标定错误诊断（GT 口径问题的真正根因）

> 本次诊断结论推翻了先前「GT 缺横担外伸」的判断。真正根因是 **DXF 立面图
> 比例尺标定错误**，导致横担外伸被放大 5 倍，3D 重建产生大量悬空节点、
> 无法匹配 GT。这是「GT 口径」问题的正确解法入口。

---

## 1. 现象链

无 GT 半宽（`use_gt_half_width=false`）重新生成 JC1 模型后：

```text
deliver status: failed
悬空断裂节点（Degree=1）846 个，应 <= 4
连通分量 347（应为 1）
A2 2D recall 1.6% @500mm
```

## 2. 诊断过程（证据链）

### 2.1 横担外伸节点被四向镜像成对角幽灵节点

`expand_4_face_symmetry` 的 `face_maps` 在无 GT 半宽时退化到 `w=abs(t)`，
横担外伸节点（|t|=6124）被镜像成 `(6124, 6124)` 对角幽灵节点 → degree=1 悬空。

### 2.2 误判「GT 缺横担」

初步对照发现 GT 塔头段半宽只有 662mm，横担外伸 2200mm，而 DXF 立面
横担外伸到 7314mm，误以为「GT 计算模型省略了横担外伸」。

### 2.3 决定性发现：比例尺标定错误

查 DXF 尺寸标注（图纸自带权威证据，非 GT）：

```text
DXF text="5800" 的尺寸标注，实际图纸测量距离 = 58.28 单位
→ 真实 scale = 5800 / 58.28 = 99.5 ≈ 100（1:100）
```

而 overlay 硬编码 `scale_x=20, scale_y=20`（1:20）。**差了 5 倍。**

### 2.4 逐 sheet 比例尺统计（关键）

各段塔身 sheet 的横向尺寸标注比例**各不相同**（国网图纸逐段不同比例）：

| sheet | 横向 scale（尺寸标注反推） | 当前 overlay 配置 |
|-------|---------------------------|-------------------|
| 02（塔头） | ~~100~~ | 20 ❌ |
| 04 | ~~100~~ | 20 ❌ |
| 05 | **20** | 20 ✅ |
| 06 | **20** | 20 ✅ |
| 07 | **10** | 20 ❌ |
| ~~40（塔底）~~ | ~~100~~ | — ❌ |

> ❌ **本表已部分推翻（2026-08-30 订正）**：
> 1. **`40` 不是塔底立面**，是构件加工详图，已从 merge 移除，无比例可言。
> 2. **「02/04 主视图真实 1:100」结论错误**。后续实测（`scale_calibration.py`
>    众数标定 + 图纸自证）确认 **02/04 主视图就是 1:20**：
>    - 02 塔身宽：图上标注 **1212mm** ↔ 腿间距 60.6u × 20 = 1212mm，精确吻合；
>      GT 在 z=30000 的塔身宽 1324mm（+80mm 修正后 1292，误差 2.4%）。
>    - 02 的 region 半宽 ±1550mm ≈ GT 横担外伸 1538mm（1:20 下自洽）。
>    - 02 最长杆 267.4u × 20 = 5348mm = BOM 最长件 5348mm。
>    - 04 的 region 反算半宽 ±1350mm ≈ GT z=23000 的 ±1152（+80 修正后吻合）。
> 3. **真正的机制**：每张图内 scale≈100 的标注属于**本段的 1:100 单线小图**，
>    不是主视图比例。取比例必须按**众数**（样本数最多的档位），不能取中位数
>    或最大值——取最大值会把 1:100 小图当成主视图比例，这正是本表误判的来源。
> 4. 「07 主视图 1:10」同样存疑：07 主域内 scale 20 的样本占 20 条，是众数。
>
> 其余结论（逐 sheet 比例混杂、需分区域标定、由此建 `scale_calibration.py`）仍成立。

## 3. 根因

1. overlay 里 6 段塔身 sheet 硬编码 `scale_x=20, scale_y=20`，但真实比例
   **逐 sheet 不同**（10/20/100 混用），是手工填写的错误值。
2. 02 塔头段真实 1:100 被配成 1:20，横担外伸被放大 5 倍（7314mm → 真实约 1463mm），
   与 GT 横担外伸 1538mm 基本吻合（验证：7314/5 = 1463 ≈ 1538）。
3. 比例尺错误导致 3D 四面展开时横担节点严重超长，四向镜像产生大量悬空幽灵节点。

## 4. 正确修复方向（阶段 3 比例尺标定）

**从图纸尺寸标注自动标定真实比例**（图纸自带的权威证据，非 GT，不违反
GT 隔离红线）：

1. 解析每张 sheet 的 DIMENSION 实体，提取「文字值 vs 测量距离」。
2. 按主视图 / 详图区域聚类（主视图比例大、详图比例小），分别标定 scale_x/scale_y。
3. 用标定后的 scale 覆盖 overlay 硬编码的 `scale_x/scale_y`。
4. 校验：标定后塔高、横担外伸应分别对齐 GT 的 36600mm 与 ~1500mm 量级。

## 5. 待验证假设

- [ ] 标定后 02 塔头横担外伸 ≈ 1463mm（vs GT 1538mm，误差 5%）
- [ ] 标定后各段塔身半宽对齐 GT 四棱台收窄规律（2762 → 200mm）
- [ ] 标定后四面展开悬空节点大幅下降（846 → 接近 0）
- [ ] 标定后 A2 2D recall / M3 3D recall 显著提升

## 6. 红线约束

- 标定只依赖**图纸尺寸标注**（DIMENSION 实体），**严禁**用 GT 反推比例。
- 标定结果写入 per-sheet model，保留 `scale_origin="dimension"` 证据。
- 不做「统一比例」假设——逐 sheet、逐区域标定。
