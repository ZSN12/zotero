## 用户问题
「CJ1 里的文件拼起来不是完整的铁塔吗？」

## 答案：拼起来是 8 座重叠的塔，不是 1 座

`batch-jc1/dxf/` 的 49 个文件是按 **8 个呼称高（9m/12m/15m/18m/21m/24m/27m/30m）** 组织的整套图纸，
与 GIM `.mod` 文件的 `HNum,8` + `H,9000~30000` 完全对应。

## 30m 塔（= GT）的 11 段结构（y 从底到顶）

```
41(-14086) → 40(-13515) → 39(-12937) → 38(-12382) → 37(-11861)
→ 07(-11297) → 06(-10511) → 05(-9974) → 04(-9151) → 03(-8352) → 02(-7694)
```

❌ **订正（2026-08-30）**：上面这条「11 段链」是**误读**——那些 y 值只是各分册
DXF 在原图版面上的摆放位置，不代表塔的标高堆叠顺序。`37`–`41` 是加工详图
（其 y 坐标恰好递增是因为详图在原册上按顺序排版的巧合），不构成塔的底段。

其中：
- `40`(z=0-5500) / `07`(z=5500-11000) / `06`(z=11000-16000) / `05`(z=16000-23000) /
  `04`(z=23000-29800) / `02`(z=30000-36600) —— **6 张曾配置 z_offset**
  ❌ **`40` 已于 2026-08-30 移除**（实测为加工详图，非立面），现仅 5 张参与 merge
- **`03`(塔头段, y[-8352,-7970]) 未合并（kind=detail），是真正漏掉的塔头段**
- `37`/`38`/`39`/`41` ~~是 30m 塔的不同接腿变体~~
  ⚠️ **修正**：与 `40` 同为**构件加工详图**（几何同构的倒三角桁架 + BOM，
  段高标注 2500/3500/4500/5500/6500 等差 1000mm——「接腿变体」假设未被证伪，
  但无论哪种解释，**它们都不能进 3D merge**）。底段立面客观缺失。

## 结论（Round 49-50 验证后修正）

1. 「拼起来」= 8 座塔重叠，必须按 30m 呼称高过滤（与 `.mod`→`.NODE` 过滤同理）
2. ~~我之前处理的 6 张 body 图是对的（`02`/`04`/`05`/`06`/`07`/`40`）~~
   **修正（2026-08-30）**：正确的是 **5 张（`02`/`04`/`05`/`06`/`07`）**。
   `40` 是加工详图，混入会导致底段杆件穿插错乱，已移除并提交。
   `03` 是塔头「节点大样」（kind=detail），`37`-`41` 是构件加工详图，都不是漏掉的塔身段
3. **scale_y=20 不是 bug**：z 坐标靠「线性归一化」（每段几何 [lo,hi] → [0,z_span] 再叠加
   z_offset，见 `tower_views.py:731-738`），scale_y 对最终 z 无影响。改 scale_y 实测零变化。
4. **layer 0 不是漏掉的杆件源**：layer 0 长线里 86 水平 + 19 竖直是尺寸界线/引出线，
   只有 17 斜线疑似杆件，且仅 7% 两端命中 layer1/4 节点。原测试断言
   「layer0 为尺寸界线不得进杆件」是对的。盲目加 layer0 实测：召回 40.8%→44.6%，
   但精度 27%→16.3%（引入 ~1300 根尺寸噪声），净害。

## 召回缺口（diag 26%/horiz 12.7%）的真实根因（已验证）

| 类型 | 根因 | 是否可解 |
|---|---|---|
| leg 78% | 画成长线，抽取良好 | 已达标 |
| diag 26% | 腹杆被画成碎片（07 段 423 斜线里 333 根 <5 单位）+ 双线（~1/3 成对）| 部分可解 |
| horiz 12.7% | 横隔在 X-Y 平面（跨塔截面），前立面(XZ)只显示短 x 投影；平面图只有 z=0 一层 | **结构性无解** |

### 已尝试的修复与结果（均回退，因过度合并/引入噪声）

- 加 layer0：召回 +3.8 但精度 -10.7（噪声），回退
- 扩展 collinear_merge 到 6 段：diag 召回 30.6%→23.2%（过度合并），回退
- 启用 double_line_merge：diag 召回 26%→19.6%（误并不同腹杆），回退

## 结论

**DXF 图纸路径存在结构性天花板（~40% 召回）**：
- 腹杆碎片化 + 双线是加工详图固有特征，任何合并参数都会「要么过度合并、要么碎片残留」
- 横隔在 X-Y 平面，前立面图结构上无法表达，只有 1 张平面图（z=0），
  horiz 召回被钉死在 ~13%
- 完整塔身（358 节点/1071 杆 100% 对齐 GT）只能走 `.mod` 结构文件（L0 canonical.glb 已达成）

## 下一步（若继续 DXF 路径）

1. 腹杆：用「端点聚类 + 节点图连通性」引导合并（而非纯几何 collinear），
   只合并「两端都命中已知节点」的碎片，避免误并不同腹杆
2. 横隔：接受结构性上限，或补充多 z 层平面图数据源
3. 否则以 L0 canonical（`.mod`）为交付主路径，DXF 仅作辅助校验
